## 1. 背景与目标

### 1.1 背景

需要一个"简单、打开即玩"的五子棋游戏。当前仓库为空仓库（仅有 README），没有既有技术栈约束，因此本设计从零规划。

### 1.2 目标

1. 在浏览器中提供完整的 15×15 五子棋对局：黑棋先行、双方轮流落子、先连成五子者胜。
2. 零后端、零第三方运行时依赖，双击 `index.html` 即可游玩（不要求本地服务器）。
3. 核心规则逻辑与界面解耦，可被 Node 原生测试直接覆盖。
4. 为后续"人机对战""复盘记谱""联网对战"预留清晰扩展点。

### 1.3 非目标（本阶段不做）

- 不做联机对战、账号体系、排行榜。
- 不做专业禁手规则（三三禁手、四四禁手、长连禁手）与 Renju 规则。
- 不做工程化构建链（Webpack/Vite/TypeScript），保持零构建。
- 不做移动端 App 打包。

## 3. 技术选型

### 3.1 总体选型

**方案：原生 HTML + CSS + JavaScript（ES2017+），多文件、非模块脚本，Canvas 2D 绘制棋盘。**

### 3.2 选型对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 单文件 `index.html`（内联全部代码） | 分发最简单 | 逻辑无法被 Node 单测覆盖，文件膨胀 | 否 |
| 原生 JS 多文件 + ES Modules | 模块边界清晰 | `file://` 下浏览器禁止加载 module，必须起本地服务器 | 否 |
| 原生 JS 多文件 + 经典 `<script>`（UMD 兼容） | 双击可玩，逻辑可被 Node `require` 后单测 | 需约定全局命名空间 | **采用** |
| React/Vue + 构建链 | 组件化、生态好 | 引入构建与依赖，超出"简单游戏"范围 | 否 |
| 纯 DOM 表格棋盘 | 易实现、可访问性好 | 15×15 共 225 个节点，悬停/动画/高亮绘制成本高、视觉粗糙 | 否 |

### 3.3 渲染选型：Canvas 2D

- 棋盘线、星位、棋子、胜负连线统一绘制，坐标计算集中在渲染层，避免 225 个 DOM 节点的样式与事件开销。
- 通过 `devicePixelRatio` 缩放保证高分屏清晰。
- 落子命中检测：像素坐标 → 最近交叉点，误差 > 0.5 格视为无效点击。

## 5. 数据模型设计

### 5.1 棋盘表示

- 使用 `Int8Array(size * size)` 一维数组，索引 `index = y * size + x`。
- 取值：`EMPTY = 0`、`BLACK = 1`、`WHITE = 2`。
- 选择一维定长数组：内存连续、遍历快、天然支持快照复制（`new Int8Array(old)`）。

```js
export const EMPTY = 0;
export const BLACK = 1;
export const WHITE = 2;

export function createBoard(size = 15) {
  return new Int8Array(size * size); // 全部为 0
}

export const idx = (x, y, size) => y * size + x;
export const inBounds = (x, y, size) => x >= 0 && x < size && y >= 0 && y < size;
```

### 5.2 对局状态

```js
/**
 * @typedef {Object} GameState
 * @property {number} size            棋盘边长，默认 15
 * @property {Int8Array} board        棋盘，长度 size*size
 * @property {1|2} turn               当前执子方（初始为 BLACK）
 * @property {Array<Move>} history    落子历史，用于悔棋与渲染
 * @property {'playing'|'finished'} status  对局状态
 * @property {null|1|2|'draw'} result 结果：黑胜 / 白胜 / 平局
 * @property {null|{x:number,y:number,x1,y1,x2,y2}} lastMove 最后落子与胜负连线
 */

/**
 * @typedef {Object} Move
 * @property {number} x
 * @property {number} y
 * @property {1|2} color
 * @property {number} no  手数，从 1 开始
 */
```

对局状态为**单一可变对象**，由 `core.js` 内部维护，导出只读快照；UI 每次操作后整体重绘，避免状态漂移。若后续需要时间旅行调试，可切换为不可变状态（每次 `place` 返回新对象），MVP 不需要。

## 6. 核心算法设计

### 6.1 落子

```
place(game, x, y):
  1. 若 status !== 'playing'            -> 返回 { ok:false, reason:'GAME_OVER' }
  2. 若 (x,y) 越界                       -> 返回 { ok:false, reason:'OUT_OF_BOUNDS' }
  3. 若 board[idx] !== EMPTY             -> 返回 { ok:false, reason:'OCCUPIED' }
  4. 写入 board[idx] = turn，push history
  5. win = checkWin(board, x, y, turn)
  6. 若 win 命中                        -> status='finished', result=turn
     否则若 history.length === size*size -> status='finished', result='draw'
     否则                               -> turn = 另一方
  7. 返回 { ok:true, move, win, draw }
```

**设计要点**：所有非法操作都通过返回值表达，不抛异常，UI 只负责提示，不负责规则判断。

### 6.2 胜负判定（以最后落子为中心的四方向扫描）

只检查最后一步棋的四个方向，复杂度 O(4 × 2 × size) 最坏约 O(120)，无需全盘扫描；该结论对标准五子棋成立：任何新产生的五连必然经过最新落子。

```js
const DIRS = [
  [1, 0],  // 横
  [0, 1],  // 竖
  [1, 1],  // 主对角线
  [1, -1], // 副对角线
];

/**
 * @returns {null | {line: number[][]}} 命中时返回构成五连（可能更长）的坐标
 */
export function checkWin(board, size, x, y, color) {
  for (const [dx, dy] of DIRS) {
    const cells = [[x, y]];
    // 正向延伸
    for (let nx = x + dx, ny = y + dy; inBounds(nx, ny, size) && board[idx(nx, ny, size)] === color; nx += dx, ny += dy) {
      cells.push([nx, ny]);
    }
    // 反向延伸
    for (let nx = x - dx, ny = y - dy; inBounds(nx, ny, size) && board[idx(nx, ny, size)] === color; nx -= dx, ny -= dy) {
      cells.unshift([nx, ny]);
    }
    if (cells.length >= 5) return { line: cells };
  }
  return null;
}
```

**边界情况**：

- 贴边落子：`inBounds` 保证不越界访问；一维数组越界会返回 `undefined`，即使漏判也不等于 `color`，但仍显式判界以求正确性。
- 长连（6 子及以上）：`cells.length >= 5` 判胜（假设 A1），胜负连线会高亮全部连子。
- 一步同时形成两个五连：命中第一个方向即返回，结果均为胜，不影响判定。

### 6.3 平局判定

`history.length === size * size` 且无五连 → 平局。注意必须在落子后、换手前判断。

### 6.4 悔棋

```
undo(game):
  1. 若 history 为空 -> 返回 { ok:false, reason:'NOTHING_TO_UNDO' }
  2. 取出最后一步 move，board[idx] = EMPTY，history.pop()
  3. status = 'playing'，result = null，lastMove = 新的栈顶（可能为 null）
  4. turn = move.color   // 回退到该步的执子方
  5. 单人模式（人机）下额外回退 AI 的一步，直到轮到人类或栈空
  6. 返回 { ok:true }
```

**为什么允许终局后悔棋**：误判/误触后可继续对局；UI 在终局后点击"悔棋"自动恢复 `playing`。

### 6.5 简单 AI（P1）

**目标**：不追求棋力，追求"会堵四、会成三、落子不违和"，单步决策 < 300ms。

1. **候选点生成**：仅考虑已有棋子周围距离 ≤ 2 的空点；空棋盘首手取天元 `(7,7)`。候选数通常 < 100。
2. **棋型评分**：对每个候选点，分别计算"己方落子后"与"对方落子后"的棋型分：

   | 棋型 | 说明 | 分值 |
   | --- | --- | --- |
   | FIVE | 成五 | 10,000,000 |
   | OPEN_FOUR | 活四 | 1,000,000 |
   | FOUR | 冲四/眠四 | 100,000 |
   | OPEN_THREE | 活三 | 10,000 |
   | THREE | 眠三 | 1,000 |
   | OPEN_TWO | 活二 | 100 |
   | TWO | 眠二 | 10 |

3. **决策**：`score(cell) = attack(cell) × 1.0 + defense(cell) × 0.9`，取最高分；同分时偏向更靠近棋盘中心的点以增加变化。`defense` 用"对方在此落子"的棋型分衡量威胁。
4. **可选增强**：深度 2 极小化极大搜索（只对 Top-10 候选展开），作为"中等难度"上线，不影响 MVP。

**风险**：启发式 AI 可能出现"只顾进攻不防守"；通过 defense 权重与先检查必胜/必堵的短路规则（己方有成五点 → 直接下；对方有成五点 → 直接堵）缓解。

### 6.6 复杂度小结

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 落子 + 胜负判定 | O(size) | 四方向线性扫描 |
| 悔棋 | O(1) | 数组弹出 |
| 重绘 | O(size²) | 225 个点，可忽略 |
| AI 简单难度 | O(K × 4 × size) | K 为候选点数 |

## 7. 接口设计（规则层 API）

```js
/**
 * 创建新对局
 * @param {{size?: number}} [options]
 * @returns {GameState}
 */
export function createGame(options = {});

/**
 * 落子
 * @param {GameState} game
 * @param {number} x
 * @param {number} y
 * @returns {{ok: true, move: Move, win: null|{line:number[][]}, draw: boolean}
 *          | {ok: false, reason: 'GAME_OVER'|'OUT_OF_BOUNDS'|'OCCUPIED'}}
 */
export function place(game, x, y);

/**
 * 悔棋（可退多步）
 * @param {GameState} game
 * @param {number} [steps=1]
 * @returns {{ok: boolean, reason?: string}}
 */
export function undo(game, steps = 1);

/**
 * 重置
 * @param {GameState} game
 * @returns {GameState}
 */
export function reset(game);
```

**约定**：规则层所有函数不读写 DOM、不依赖时间、不使用 `Math.random`，保证同一输入必然同一输出，便于单测与复盘回放。

## 8. 界面与交互设计

### 8.1 页面布局

```
+---------------------------------------------------+
|  五子棋                              [模式: 双人] |
+----------------------------------+----------------+
|                                  |  当前执子 ● 黑  |
|                                  |  手数  12       |
|         Canvas 棋盘               |  状态  对局中   |
|         15×15 网格                |                |
|         星位 ●                     |  [悔棋]        |
|         高亮最后落子               |  [重新开始]    |
|                                  |  [模式切换]    |
+----------------------------------+----------------+
|  对局结果提示区（胜利/平局/错误提示）              |
+---------------------------------------------------+
```

- 桌面：棋盘 + 右侧信息栏两列布局；宽度 < 720px 时改为上下单列，棋盘自适应。
- 棋盘尺寸：`cellSize = floor(min(可用宽, 可用高) / (size + 1))`，四周留一格边距。
- 视觉：浅木色棋盘背景、深色网格线、黑白棋子带径向渐变与阴影，最后落子加红色小圆点，胜利五连加半透明高亮条。

### 8.2 交互流程

```
页面加载 → createGame() → 绘制棋盘 → 等待输入
   │
   ├─ 点击/悬停棋盘
   │    ├─ 悬停：计算最近交叉点，绘制半透明预落子
   │    └─ 点击：place() 
   │           ├─ ok=false → 状态区提示原因，不重绘棋盘
   │           └─ ok=true  → 重绘 → 更新面板
   │                  ├─ win  → 绘制胜利连线，提示"黑棋获胜"，禁用落子
   │                  ├─ draw → 提示"平局"
   │                  └─ 继续 → 人机模式下触发 AI 落子
   ├─ 悔棋 → undo() → 重绘 → 恢复 playing
   └─ 重新开始 → reset() → 重绘
```

### 8.3 状态机

| 当前状态 | 事件 | 下一个状态 | 附加动作 |
| --- | --- | --- | --- |
| `playing` | 点击空点且合法 | `playing` / `finished` | 落子、判胜负、换手 |
| `playing` | 点击非法点 | `playing` | 提示错误 |
| `playing` | 悔棋且历史非空 | `playing` | 回退 |
| `finished` | 悔棋 | `playing` | 清除结果、回退一步 |
| `finished` | 点击棋盘 | `finished` | 提示"对局已结束" |
| 任意 | 重新开始 | `playing` | 清空全部状态 |
| `playing` | 人机模式 AI 回合 | `playing` / `finished` | AI 落子，期间锁定输入 |

### 8.4 异常与边界处理

| 场景 | 处理方式 |
| --- | --- |
| 点击已有棋子 | 忽略 + 状态栏提示"该位置已有棋子" |
| 点击棋盘外/两格之间 | 最近交叉点距离 > 0.5 格则忽略 |
| 终局后继续点击 | 忽略 + 提示"对局已结束，请悔棋或重新开始" |
| AI 思考中玩家点击 | 输入锁定（`isAiThinking` 标志），避免双方同时落子 |
| AI 无合法点（棋盘已满） | 按平局结算 |
| 窗口尺寸变化 | 重新计算画布尺寸并重绘，棋盘状态不变 |
| 高分屏模糊 | 按 `devicePixelRatio` 放大画布并 `ctx.scale` |

| T-14 | 历史为空时悔棋 | 返回 `NOTHING_TO_UNDO` |
| T-15 | 终局后悔棋 | 回到 `playing`、`result=null` |
| T-16 | 重新开始 | 棋盘全空、先手黑棋、历史清空 |
| T-17 | 贴边五连 | 边界处五连正确判胜，不越界 |
| T-18 | 胜负判定幂等 | 同一局面重复调用 `checkWin` 结果一致 |

### 9.2 手工验收清单（浏览器）

1. 双击 `index.html`（`file://`）可直接进入对局，控制台无报错。
2. 黑先白后交替，落子位置与鼠标点击一致。
3. 任意方向连成 5 子立即提示获胜并锁定棋盘。
4. 棋盘下满提示平局。
5. 悔棋可连续点击，棋盘与手数同步回退。
6. 重新开始后回到空盘、黑棋先手。
7. 缩放到 320px 宽仍可正常落子，棋盘不溢出。
8. 高分屏下棋盘线条清晰不模糊。
9. 人机模式下 AI 在 300ms 内完成落子，不会连下两步。

### 9.3 回归策略

## 10. 性能与兼容性

- **重绘**：整盘重绘 225 个点，Canvas 2D 在普通设备上 < 2ms；悬停重绘合并到 `requestAnimationFrame`，避免高频事件抖动。
- **DOM 更新**：状态面板使用 `textContent` 定点更新，不整体替换。
- **内存**：单局状态 < 10KB。
- **兼容性降级**：不支持 Canvas 的极老浏览器显示提示文案，不做 polyfill。
- **无构建**：脚本按 `core.js → ai.js → ui.js` 顺序以经典 `<script>` 引入，兼容 `file://`。

## 12. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
| --- | --- | --- | --- |
| `file://` 下 ES Modules 被拦截 | 双击无法启动 | 高 | 采用经典脚本 + UMD 风格导出（已在选型中规避） |
| 胜负判定漏判贴边/对角 | 规则错误 | 中 | 四方向表驱动 + 边界单测 T-05~T-09、T-17 |
| 悔棋后状态不一致 | 越下越乱 | 中 | 所有状态围绕 `history` 重建；单测 T-13~T-15 |
| AI 太弱或过慢 | 体验差 | 中 | 候选点裁剪 + 必胜/必堵短路；打分表可调 |
| 高分屏棋盘模糊 | 视觉差 | 中 | `devicePixelRatio` 缩放（已列入验收） |
| 规则歧义（长连/禁手） | 需求返工 | 低 | 假设 A1 明确为无禁手自由规则，后续按扩展项处理 |
